## What the machine found

axe-core 4.11.4, tags `wcag2a wcag2aa wcag21a wcag21aa wcag22aa`, at both viewports.

**Before — 4 violations across 37 nodes:**

- `color-contrast` (serious, **34 nodes**) — the whole page. Body text `#8b93a1` on white is
  2.72:1; nav links `#b9d2ee` on `#2b6cb0` and the ghost buttons at `#aab6c8` are worse.
- `html-has-lang` (serious, 1) — no `lang`, so screen readers guess pronunciation.
- `image-alt` (critical, 1) — the payments badge has no alt text.
- `button-name` (critical, 1) — the empty icon button in the header has no accessible name at all.

**After — 0 violations, 29 passes desktop / 30 mobile**, with load proof recorded (103 elements,
1045 characters of rendered text, 62 rules considered). The zero means axe ran on a real page.

## What the machine could not find

This is the part that matters, and it is why the identity says automated checks are a floor.
Each of these is a genuine defect in `before/` that **axe reported nothing about**:

- **Placeholder-as-label.** Both filter inputs are labelled only by `placeholder`. axe's `label`
  rule *passes*, because a placeholder does supply an accessible name — but the name vanishes the
  moment the user types, and it never has a visible persistent label. Fixed with real `<label>`
  elements plus an `aria-describedby` hint.
- **`<div onclick>` as a button.** Four "Send" controls are divs with no `role`, no `tabindex` and
  no key handling. axe cannot flag them because a div with no interactive role is, as far as the
  DOM is concerned, just a div. They are keyboard-unreachable. Now real `<button>`s.
- **Colour-only status.** Paid/overdue was a bare coloured dot with no text. Passes contrast, means
  nothing to anyone who cannot distinguish the hues, and nothing at all to a screen reader. Now an
  icon plus the words "Paid" / "Overdue".
- **Non-specific action names.** Four identical "Send" controls; out of context a screen-reader
  user hears "Send" four times. Now "Send reminder for MRD-1040".
- **12px body copy and justified text** with `line-height: 1.25` — no violation exists for
  "too small and hard to read". Now 16px at 1.6, ragged right, capped at a 68ch measure.
- **`:focus { outline: none }`** on both button classes with no replacement. axe does not simulate
  focus, so it says nothing. Now a 2px ring at 2px offset, 5.82:1 against the page.
- **Sub-24px targets.** The header icon button is 17×17 and the ghost buttons are ~20px tall,
  against WCAG 2.2 SC 2.5.8. Automated target-size checking is unreliable, so this was measured by
  hand. Everything interactive is now ≥44px.
- **Disabled with no explanation.** "Cancel plan" was disabled with no clue what would enable it.
  Now `aria-describedby` points at a sentence that says when it becomes available.
- **No skip link, no landmarks, unheaded structure.** The before page opens with `<h3>` and skips
  to `<h5>` — technically no heading-order violation because there is no `h1` to order against.
  Now `h1`/`h2`, a `<header>`/`<nav>`/`<main>`/`<footer>` skeleton, and a skip link first in tab
  order.
- **No `<th scope>` or caption** on the data table; the header row was `<th>` inside an implicit
  tbody with no scope. Now `<thead>`, row headers with `scope="row"`, and a caption.

## Design changes, and why

- **Type**: single 1.25 scale off 16px; page title at 39px, body 16/1.6, dense metadata 14px.
  Measure capped at 68ch — the before page ran text edge to edge at ~180 characters.
- **Colour**: one accent. The before screen used blue for the header, a different blue for the
  primary button, and a third for links. Now `accent-600` fills the one primary action per group,
  `accent-700` carries links.
- **Spacing**: everything on the 4px grid, 8/16/24/48 rhythm. The before layout used 3, 5, 7, 9, 11,
  13, 18, 21, 26px — arbitrary values that read as noise.
- **Motion**: colour transitions at 120ms with the standard curve, and nothing else moves.
  `prefers-reduced-motion` collapses them to 1ms via the generated token block, and the
  screenshots are taken with reduced motion forced so captures are deterministic.
- **Mobile**: the before page has no viewport meta, so it renders desktop-width and is
  pinch-zoomed — visible in the mobile screenshot as a lower ink ratio (2.02% vs 7.07%). The after
  page stacks the bar, drops the title to 31px, and lets inputs go full width.

## Honest notes

- The after page is a **static HTML sample**, not a production integration. No framework, no build
  step, no data layer.
- Contrast numbers come from `tools/tokens.mjs` over the token file; per-element contrast on the
  before page comes from axe. Both are recomputed by the gate.
- Hand-reviewed items above were reviewed by reading the markup and the rendered screenshots. They
